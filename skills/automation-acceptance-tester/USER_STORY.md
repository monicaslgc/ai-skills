# User story: automation-acceptance-tester

## Audience
A practitioner who needs to turn process requirements into normal, boundary, failure, retry and approval test cases..

## Scenario
The user provides incomplete context and wants a repeatable result without unsupported assumptions.

## Acceptance criteria
- Scope and available evidence are identified.
- Facts, assumptions and unknowns are distinguishable.
- Output is actionable and covers edge cases.
- Validation checks are explicit.
- Consequential changes require human approval.

## Try it
> Turn process requirements into normal, boundary, failure, retry and approval test cases. Use a small fictional example. State assumptions, include an edge case and explain how to verify the result.
