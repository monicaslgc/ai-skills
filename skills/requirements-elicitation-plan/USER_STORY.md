# User story: requirements-elicitation-plan

## Story

**As** someone about to specify a new feature or system,
**I want** a plan to discover what people really need,
**so that** we build for the real process and not for a guess.

## Scenario

A team will replace an approval tool used by finance, procurement and branch managers. Each group describes the process differently and nobody has documented the exceptions.

## Acceptance criteria

- [ ] A stakeholder map that includes the groups that are rarely heard.
- [ ] A technique chosen for each group, with the reason.
- [ ] Questions by theme that ask for real examples.
- [ ] A session plan, capture templates and a log of needs with their sources.
- [ ] A way to validate findings and reconcile conflicts.
- [ ] Unknowns and risks listed.
