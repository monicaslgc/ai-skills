# Support kpi dashboard designer

Measure what matters, define it once, and show it so people act on it.

## Inputs to collect

Ask for what is missing, or mark it as unknown:
- Goals of the support function.
- Data available from the ticketing system.
- Audiences: agents, team leads, managers.
- Existing reports and complaints about them.

## Workflow

1. Start from decisions: what will someone do differently if a number moves?
2. Pick a small set of metrics across volume, speed, quality, efficiency and customer outcome (for example backlog, first response time, resolution time, first-contact resolution, reopen rate, satisfaction).
3. Define each metric exactly: formula, what is included or excluded, time zone, business hours, pause rules, and source field.
4. Set targets from history and goals. Mark proposed targets as proposed.
5. Design views by audience: a one-screen summary for managers, drill-down for team leads, and personal views for agents used for coaching, not ranking.
6. Choose visuals: trends over time, distributions instead of averages for times, clear labels and consistent colours.
7. Add context to avoid misleading conclusions: sample sizes, seasonality, changes in process, and warnings about gaming.
8. Plan data quality checks and a review cadence.

## Output format

| Metric | Definition (formula, inclusions, exclusions) | Source | Target | Audience | Visual |
|---|---|---|---|---|---|

Dashboard layout, data quality checks, review cadence.

## Safety

- Do not use a single metric to judge individuals.
- Show distributions and sample sizes, not only averages.
- Use synthetic data in shared examples.
