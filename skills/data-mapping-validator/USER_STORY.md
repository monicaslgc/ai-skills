# User story: data-mapping-validator

## Audience
A practitioner who needs to validate field mappings across systems, including ids, types, nulls, enums and transformations..

## Scenario
The user provides incomplete context and wants a repeatable result without unsupported assumptions.

## Acceptance criteria
- Scope and available evidence are identified.
- Facts, assumptions and unknowns are distinguishable.
- Output is actionable and covers edge cases.
- Validation checks are explicit.
- Consequential changes require human approval.

## Try it
> Validate field mappings across systems, including IDs, types, nulls, enums and transformations. Use a small fictional example. State assumptions, include an edge case and explain how to verify the result.
