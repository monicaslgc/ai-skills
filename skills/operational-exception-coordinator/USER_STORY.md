# User story: operational-exception-coordinator

## Audience
An operations lead or practitioner who needs to create a consistent response plan for exceptions that disrupt an operational process or service.

## Scenario
The user provides incomplete operational context and needs a repeatable, evidence-led artefact that can be reviewed before use.

## Acceptance criteria
- Severity uses supplied policy or is explicitly provisional.
- Containment and permanent correction are distinguished.
- Escalation trigger and recovery criteria are testable.
- No unauthorised action is represented as completed.
- Consequential changes remain subject to human approval.

## Try it
> Create a consistent response plan for exceptions that disrupt an operational process or service. Use fictional or approved data, include an edge case, and explain how to validate the result.
