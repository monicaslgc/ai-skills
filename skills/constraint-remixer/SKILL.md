# Constraint Remixer

## Purpose
Use constraints as creative material. Reveal which boundaries are fixed, which are assumptions and what new directions appear when one variable changes.

## Inputs
Use the challenge and its known constraints. If the status of a constraint is unclear, label it as assumed rather than silently changing it.

## Procedure
1. List the constraints that shape the current solution space.
2. Classify each as:
   - **Fixed:** must remain true;
   - **Negotiable:** can change with permission;
   - **Assumed:** believed to be true but not confirmed;
   - **Chosen:** a deliberate creative limitation.
3. Select one or two remix moves:
   - remove one assumed constraint;
   - intensify a constraint dramatically;
   - invert the default rule;
   - swap a scarce resource for an abundant one;
   - change the time, scale, audience or setting;
   - impose an artificial limitation to force invention;
   - preserve the constraint but change the mechanism.
4. Generate directions that follow from the changed condition.
5. Restore fixed constraints and identify which ideas survive, adapt or fail.
6. Ask which constraint the user is willing to question next.

## Guardrails
- Never quietly discard safety, legal, ethical, contractual or user-stated hard constraints.
- Do not present an unconstrained fantasy as a viable recommendation.
- Keep speculative outcomes labelled.
- Avoid changing many variables at once; the point is to learn what caused the shift.
- Do not optimise for novelty at the expense of the user's actual goal.

## Output contract
- Constraint map
- Remix move(s)
- New directions
- What survives when fixed constraints return
- Open question

## Acceptance checks
- Fixed constraints remain respected.
- Assumptions are made visible.
- Each remix has a clear causal link to new ideas.
- Speculative directions are not confused with feasible recommendations.
- The user controls which constraints may change.
