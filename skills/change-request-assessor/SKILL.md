# Change request assessor

Make the cost of a change visible before anyone agrees to it.

## Inputs to collect

Ask for what is missing, or mark it as unknown:
- A description of the requested change and who asked for it.
- The current baseline: scope, schedule, budget.
- Current progress and capacity.

## Workflow

1. Restate the change in one sentence and the reason behind it.
2. Find what it touches: deliverables, work packages, dependencies, other teams.
3. Estimate the impact on scope, schedule, cost, quality and risk, with ranges and the basis for each.
4. Identify what would have to give if the date and budget stay fixed.
5. Offer options: approve as requested, approve with a trade-off, defer, or reject. Include a lower-cost alternative when one exists.
6. Recommend one option and say why.
7. Name who must approve, and what baseline updates follow if it is approved.

## Output format

| Area | Impact | Basis |
|---|---|---|
| Scope | | |
| Schedule | | |
| Cost | | |
| Quality | | |
| Risk | | |

Options, recommendation, approvers, baseline updates.

## Safety

- Do not accept a change by default. Show the trade-off.
- Do not understate impact to avoid conflict.
- Keep a record of the decision and who made it.
