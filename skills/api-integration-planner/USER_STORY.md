# User story: api-integration-planner

## Audience
A practitioner who needs to plan integrations from verified api contracts, authentication, pagination, rate limits and error semantics..

## Scenario
The user provides incomplete context and wants a repeatable result without unsupported assumptions.

## Acceptance criteria
- Scope and available evidence are identified.
- Facts, assumptions and unknowns are distinguishable.
- Output is actionable and covers edge cases.
- Validation checks are explicit.
- Consequential changes require human approval.

## Try it
> Plan integrations from verified API contracts, authentication, pagination, rate limits and error semantics. Use a small fictional example. State assumptions, include an edge case and explain how to verify the result.
