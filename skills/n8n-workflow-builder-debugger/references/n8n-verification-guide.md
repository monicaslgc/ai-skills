# n8n verification guide

1. Identify the target n8n version and whether it is Cloud or self-hosted.
2. Consult current official n8n documentation for the node, operation, expressions, webhook behaviour, and error handling.
3. Consult the provider's official API docs for authentication, required fields, pagination, rate limits, idempotency, and error responses.
4. If docs are unclear, compare with a workflow export from the same or a known-compatible version. Treat community examples as clues, not authoritative guarantees.
5. Mark each material implementation detail as verified, user-provided, assumed, or unverified.
6. If documentation or a live instance is unavailable, do not fabricate parameter names or claim import compatibility. Provide a partial skeleton or explicit verification steps.

## Evidence ladder
- Drafted: generated by the assistant.
- JSON syntax checked: a parser accepted the file.
- Structurally reviewed: nodes, connections, expressions, and mappings reviewed.
- Import verified: imported successfully into the stated n8n version.
- Execution verified: an observed test execution matched expected results.
- Production observed: real production evidence gathered with authorization.

Each level requires evidence; a lower level does not imply a higher one.
