# User story: app-flow-mapper

## Story

**As** someone who has to explain or change an app they did not build,
**I want** its real flows recorded step by step with evidence,
**so that** documentation, specifications and training start from what the app does and not from what people remember.

## Scenario

A team is about to write guides for an internal tool whose old documentation is two years out of date. Nobody is sure how the approval step behaves for a user without the approver role.

## Acceptance criteria

- [ ] Flows are named as user goals.
- [ ] Every step has a screen, an action, the app's response and evidence.
- [ ] Branches, role differences and safe-to-provoke errors are recorded with the exact messages.
- [ ] Each statement is labelled observed, reported or inferred.
- [ ] Only demo data and test accounts were used.
- [ ] Gaps and differences from the old documentation are listed.
