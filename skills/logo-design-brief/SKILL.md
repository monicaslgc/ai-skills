# Logo Design Brief

## Purpose
Write a strategic brief for logo and identity designers.

## Required inputs
- User objective and required decision or deliverable.
- Relevant organisation, product, audience, market and language context.
- Existing source material, constraints and approved decisions.
- Unknowns; ask only for information that materially changes the work.

## Method
Summarise strategy, audience, positioning, personality, usage contexts, constraints, deliverables, accessibility, production needs and evaluation criteria.

## Output
1. Outcome: requested artefact or recommendation.
2. Evidence: source, date and confidence for material factual claims.
3. Assumptions and unknowns, separate from verified facts.
4. Decisions needed, owner and approval required.
5. Smallest useful next step.

## Quality and safety
- Preserve supplied source facts; do not silently fill gaps.
- Separate evidence, interpretation, hypothesis and recommendation.
- Prefer primary sources and record URLs and access dates.
- Protect confidential and personal information; use synthetic examples in public artefacts.
- Do not prescribe a logo concept so narrowly that it replaces design exploration.
- Follow the shared contracts in ../../kits/brand-strategy-identity/README.md when tools are available. If a tool is unavailable, state the limitation and provide a manual alternative.

## Decision rules
- Confirm that positioning, audience and personality are sufficiently approved; otherwise mark the brief exploratory.
- Specify intended use cases, sizes, backgrounds, reproduction methods, markets and required lock-ups.
- Define functional constraints: legibility, scalability, monochrome use, responsive variants, accessibility and file formats.
- State deliverables, source files, export formats, licensing/ownership expectations, handover and acceptance criteria.
- Provide strategic evaluation criteria (fit, memorability, distinctiveness, versatility) without prescribing a visual solution.
- Identify required checks for similarity, trademark and cultural interpretation; design review is not legal clearance.
- Include approvers, feedback rounds and decision deadline, distinguishing preference from criteria-based feedback.
