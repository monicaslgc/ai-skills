# User story: user-guide-writer

## Story

**As** a support or product person who answers the same questions every week,
**I want** a step-by-step guide for each common task,
**so that** users solve it themselves and support time goes to harder problems.

## Scenario

New users keep asking how to change the owner of a record. The old guide shows a screen that no longer exists.

## Acceptance criteria

- [ ] One task per guide, named with a verb.
- [ ] Steps use the exact labels on screen and say what the reader should see.
- [ ] Warnings come before the costly step.
- [ ] Role differences and common errors are covered.
- [ ] Version, verification date and verifier are recorded.
- [ ] Someone who has never done the task completes it with the guide alone.
