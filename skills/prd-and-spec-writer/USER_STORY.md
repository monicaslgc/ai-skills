# User story: prd-and-spec-writer

## Audience
A practitioner who needs to write product requirements with scope, user stories, rules, dependencies, telemetry and acceptance criteria..

## Scenario
The user provides incomplete context and wants a repeatable result without unsupported assumptions.

## Acceptance criteria
- Scope and available evidence are identified.
- Facts, assumptions and unknowns are distinguishable.
- Output is actionable and covers edge cases.
- Validation checks are explicit.
- Consequential changes require human approval.

## Try it
> Write product requirements with scope, user stories, rules, dependencies, telemetry and acceptance criteria. Use a small fictional example. State assumptions, include an edge case and explain how to verify the result.
